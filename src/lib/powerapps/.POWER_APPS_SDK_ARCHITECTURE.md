# Power Apps Code Apps – SDK & Bridge Architecture

> **Audience**: Developers working on `SerenaAI/src/web/open-webui` that need
> to understand how a Code App communicates with the Power Apps host and
> Dataverse.

## 2. The Bridge (`DefaultPowerAppsBridge`)

**File**: `@microsoft/power-apps/lib/internal/plugins/DefaultPowerAppsBridge.js`

The bridge is the **only** communication channel between the Code App and the
Power Apps host. It works via a `MessageChannel`:

1. On `initialize()`, the bridge sends `initCommunicationWithPort` to
   `window.parent` along with `port2` of a new `MessageChannel`.
2. The host responds with `initCommunication` + `antiCSRFToken` on `port1`.
3. All subsequent calls go through `port1.postMessage(…)`.

### `executePluginAsync(pluginName, pluginAction, params[])`

This is the core primitive. Every SDK method ultimately calls it:

```javascript
// From PluginBridge.js
export async function executePluginAsync(pluginName, pluginAction, params = []) {
    const bridge = await getBridge();
    return bridge.executePluginAsync(pluginName, pluginAction, params);
}
```

The bridge wraps the call in a Promise, assigns a `callbackId`, and sends:

```json
{
  "isPluginCall": true,
  "callbackId": "instanceId=1234_AppLifecycle0",
  "service": "AppLifecycle",
  "action": "getContext",
  "actionArgs": [],
  "antiCSRFToken": "abc123"
}
```

The host processes it and sends back a response on the same MessageChannel port:

```json
{
  "isPluginCall": true,
  "callbackId": "instanceId=1234_AppLifecycle0",
  "status": 1,
  "args": [{ "app": {...}, "user": {...}, "host": {...} }]
}
```

`status = 1` means success; anything else is an error.

| Service | Action | Description |
|---------|--------|-------------|

## 4. How Data Flows to Dataverse

The SDK's data layer (used by generated `*Service.ts` files from
`pac code add-dataverse-table`) follows this chain:

```
DataClient.retrieveRecordAsync(...)
  → DataverseDataOperationExecutor
    → RuntimeDataClient._executeRequest(config)
      → 1. _getAccessToken(apiId, datasetName)
      │    → executePluginAsync('AppIdentityServicePlugin', 'getAppDynamicResourceAccessTokenAsync', [envId])
      │
      → 2. _createHeaders(token, config)
      │    Sets: Authorization: "dynamicauth {token}"
      │    Sets: BatchInfo: { baseUrl, encodedPath, headers }
      │
      → 3. executePluginAsync('AppHttpClientPlugin', 'sendHttpAsync', [requestObj, body, 'arraybuffer'])
      │
      → 4. Parse response: [headersObj, ArrayBuffer]
```

**Key**: The host wraps Dataverse calls in an OData batch request internally.
The `dynamicauth` token type tells the host to use the dynamic Dataverse auth
flow.

For **non-Dataverse** APIs (connectors), the auth type is `paauth {token}`.

## 5. Code App vs. PCF vs. Model-Driven

| Feature | Model-Driven App | PCF Control | Code App |
|---------|------------------|-------------|----------|
| `window.Xrm` | ✅ Available | ✅ Via `context` | ❌ NOT available |
| `Xrm.WebApi.execute()` | ✅ | ✅ | ❌ |
| `@microsoft/power-apps` SDK | ❌ | Partial (context) | ✅ Full |
| Bridge (postMessage) | ❌ | ❌ | ✅ Required |
| `app.getContext()` | ❌ | ❌ | ✅ |
| `data.getClient()` | ❌ | ❌ | ✅ |

**Code Apps do NOT have access to `Xrm.WebApi`**. All communication goes
through the `DefaultPowerAppsBridge` → `executePluginAsync`.

## 6. `pac code run` Local Development

When running locally:

```bash
pac code run --port 8081
```

- Port **8081**: Local connection proxy & Power Apps host player
- Port **5173**: Vite dev server (the Code App itself)
- The host at 8081 loads an iframe pointing to `http://localhost:5173`
- URL params: `_localAppUrl=http://localhost:5173/&_localConnectionUrl=http://localhost:8081/`
- The bridge's `window.parent.postMessage` sends messages to the host at 8081
- The host proxies Dataverse calls using the authenticated user's session

## 7. Calling a Custom API from a Code App

Since `Xrm.WebApi.online.execute()` is NOT available, calling a Dataverse
Custom API requires going through the bridge:

```typescript
// 1. Get the bridge function
const { executePluginAsync } = await import(
    '@microsoft/power-apps/lib/internal/plugins/PluginBridge'
);

// 2. Get context (for environment ID)
const ctx = await executePluginAsync('AppLifecycle', 'getContext');
const envId = ctx.app.environmentId;

// 3. Get Dataverse access token
const token = await executePluginAsync(
    'AppIdentityServicePlugin',
    'getAppDynamicResourceAccessTokenAsync',
    [envId]
);

// 4. Call the Custom API via HTTP proxy
const result = await executePluginAsync(
    'AppHttpClientPlugin',
    'sendHttpAsync',
    [{
        url: `https://{org}.crm.dynamics.com/api/data/v9.2/aut_GetSsoToken`,
        method: 'POST',
        headers: {
            'Authorization': `Bearer ${token}`,
            'Accept': 'application/json',
            'OData-Version': '4.0'
        },
        returnDirectResponse: true
    }, '', 'arraybuffer']
);

// result = [headersObj, ArrayBuffer]
```

## 8. `getContext()` Response Shape

```typescript
interface PowerAppsContext {
    app: {
        appId: string;
        environmentId: string;       // e.g. "6324cac6-dbbb-e555-8bbd-4f902ee1a905"
        appSettings: object;
        queryParams: Record<string, string>;
    };
    host: {
        sessionId: string;
    };
    user: {
        fullName?: string;           // display name
        objectId?: string;           // Azure AD object ID
        tenantId?: string;           // Azure AD tenant ID
        userPrincipalName?: string;  // email / UPN
    };
}
```

## 10. CORS Considerations

- The Code App runs at `localhost:5173` (Vite)
- The Open WebUI backend runs at `localhost:8080`
- The Power Apps host runs at `localhost:8081` (pac code run)
- Direct `fetch()` from 5173 → 8081 or → Dataverse will be blocked by CORS
- The bridge **bypasses CORS** because it uses `postMessage`, not HTTP
- This is why all Dataverse calls MUST go through `AppHttpClientPlugin.sendHttpAsync`
